# 六点盲文排版台

本地运行的英语一级（Grade 1）六点盲文转写排版与识读 Web 应用。
Python / FastAPI 后端 + 原生 HTML/CSS/JavaScript 前端，**无需外网、无前端构建步骤**。

## 一条命令启动

需要已安装 Docker 与 Docker Compose（v2）。

```bash
docker compose up --build
```

启动后用浏览器访问：

> **http://localhost:8000**

停止：在终端按 `Ctrl+C`；后台方式可用 `docker compose up -d --build` 与 `docker compose down`。

端口被占用时，编辑 `docker-compose.yml` 中 `"8000:8000"` 的左侧端口即可（例如 `"18000:8000"`）。

## 不用 Docker 时（本地 Python 直跑）

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

同样访问 http://localhost:8000 。

## 功能与转写规则

### 盲文排版（原文 → 盲文）

- **输入约束**
  - 不超过 500 个 ASCII 字符：仅字母、数字、空格、换行；
  - 至少包含一个字母或数字；
  - 每个词只能全为字母或全为数字，非法字符与字母数字混写词会**定位到行、列**报错（点击错误可跳转到输入位置）；
  - 换行是**硬分段**；连续空格合并为**一个词间格**。
- **盲文转写（英语一级六点盲文）**
  - 点位编号：左列自上而下为点 1、2、3，右列为点 4、5、6；
  - 每个大写字母前加 **点 6** 大写标记；
  - 数字词以 **点 3456** 数字标记开头，数字 1～9、0 分别借用 a～i、j 的点位；
  - 输出使用 Unicode 盲文图案（U+2800 区段），词间使用 U+2800 空白盲文格。
- **排版**
  - 每行格数可设 10～40；
  - 词间格占 1 格；行首、行尾不留空格；
  - 普通词不在词内断行，**仅超宽词**可在字符间断开；断词行尾加 **点 36** 连字符；
  - 数字词跨行使，续行**重新加数字标记**；
  - 动态规划按以下顺序取最优：
    1. 断词次数最少；
    2. 行数最少；
    3. 各行剩余格数的平方和最小；
    4. 以上全相同时，取断点序列字典序最小者。
- **页面**：原文行与盲文格逐行对照；每格显示六点矩阵、盲文字符与说明（悬停查看点位）；
  显示每行用格/余格、断词与数字续行统计；支持**下载 Unicode 盲文 `.txt`**、一键复制。

### 盲文识读（盲文 → 原文）

- **输入约束**：粘贴不超过 **500 格**的 Unicode 六点盲文，允许盲文空格（U+2800）与换行。
- **识读规则**
  - 字母沿用一级点位还原；**⠠（点 6）** 只把紧随的一个字母转为大写；
  - 识读时持续记录**当前词的类型**（字母词 / 数字词）与**断词待续状态**；
  - **⠼（点 3456）** 使后续 a～i、j 点位分别读作 1～9、0；数字标记只能在词首
    （行首或盲文空格之后）**开启数字词**，或在数字词断行续行行首**重新起始**；
    数字状态到词间格或普通换行结束；
  - **⠤（点 36）** 仅作行尾断词标记：去掉该格及其后的换行并接续同一词；
    标记前必须有同一行内未结束的词，续行首格必须是**同一类型**的未结束词
    （字母续字母、数字以 ⠼ 重新起始）；盲文空格与普通换行终止词，普通换行保留。
- **报错**：孤立标记、未定义点位、行内连字符、标记前无未结束词、数字标记误入
  字母词、断行前后词类型不一致与不合法的数字续行均**按盲文行、列定位**
  （点击错误可跳转），且不输出部分解读文本。
- **页面**：顶部标签切换各功能视图；识读结果显示原文与格数/字符数/行数统计，支持一键复制。

### 双面点阵避让（正反对印）

- **入口**：页面顶部「双面避让」标签，或 `POST /api/avoid`。
- **输入**：正面原文、反面原文（各自复用盲文排版的全部校验与排版规则）、共同行宽（10～40 格）、
  最小点距（0.1～3.0 毫米，限一位小数）；两面的输入错误带「正面 / 反面」标记并定位到行、列。
- **坐标**：零基行格 (r, c) 中，点 1～3 坐标为 (6c, 10r+2.5k)，点 4～6 为 (6c+2.5, 10r+2.5k)，
  k=0～2，单位毫米，只计凸点；反面点 (x, y) 映射到正面坐标 (6(w−1)+2.5−x+dx, y+dy)。
- **避让搜索**：dx、dy 各取 −3～3 毫米、步长 0.1 毫米，遍历全部 61×61 个位移；
  两面点距小于最小点距记一对冲突（以放大 10 倍的整数平方比较距离）；
  按 **冲突对数 → dx²+dy² → dx → dy** 依次最小择优。
- **结果**：返回最优位移与全部冲突点对（两端均附面、行、格、点号，零基）；
  零冲突显示**可行**，否则说明**仍有冲突**；页面叠加两面点阵并以红圈、连线标出冲突点对。

### 压印点位复核（理论点 ↔ 实测点）

- **入口**：页面顶部「压印复核」标签，或 `POST /api/inspect`。
- **输入**：不超过 **100 字符**的合法原文（复用盲文排版的全部校验与排版规则）、行宽（10～40 格）、
  以及 **0～400 行**实测凸点；每行一对 **x,y**（毫米，限一位小数，可带负号），按输入顺序编号，
  结尾单个换行不产生空行；原文或坐标错误均**按位置报错**（原文报行、列，坐标报实测点行、列）。
- **坐标**：沿用排版结果的理论凸点坐标（同避让口径，零基行格，只计凸点）；
  实测点整体平移 dx、dy（各 −3～3 毫米、步长 0.1 毫米），遍历全部 61×61 个位移。
- **配对**：位移后实测点与理论点距离不超过 **0.4 毫米**才可配对，且双方均**一对一**；
  候选对按（距离平方, 实测点输入行序, 理论点序号）升序贪心选取，
  同一理论点有多个候选时取最近者，同距取输入顺序较早者。
- **择优**：依次取 **匹配点数最多 → 距离平方和最小 → dx²+dy² 最小 → dx 最小 → dy 最小**。
- **结果**：返回最优位移、**缺失理论点**的零基行/格/点号、**多余实测点**的输入行号（一基）
  及原始坐标、全部配对（含间距）、距离平方和与完整排版结果；
  页面叠加图中以红圈标出缺失理论点、红菱形标出多余实测点，列表点击可定位到对应输入行。

## API

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| `POST` | `/api/typeset` | 请求体 `{"text": "...", "width": 20}`，返回排版结果；输入非法时 HTTP 422，`errors` 含行/列定位 |
| `POST` | `/api/decode` | 请求体 `{"text": "..."}`（Unicode 六点盲文，≤500 格），返回 `{"text": ...}` 识读结果；输入非法时 HTTP 422，`errors` 含盲文行/列定位，不返回部分结果 |
| `POST` | `/api/avoid` | 请求体 `{"front": "...", "back": "...", "width": 20, "min_distance": 1.0}`，返回最优位移 `dx`/`dy`、`feasible` 与全部冲突点对（两端含面/行/格/点号，零基）及两面排版结果；输入非法时 HTTP 422，原文错误带 `face` 区分正反面 |
| `POST` | `/api/inspect` | 请求体 `{"text": "...", "width": 20, "points": "0.1,0.2\n2.6,-0.1"}`（原文 ≤100 字符，实测点 0～400 行、每行一对一位小数坐标），返回最优 `dx`/`dy`、`matched`/`missing`/`extra` 计数、`missing_dots`（零基行/格/点号）、`extra_points`（输入行号与原始坐标）、`matches`（含间距与输入行号）、距离平方和 `sse` 与排版结果 `layout`；输入非法时 HTTP 422，错误带 `field`（`text`/`points`）与行、列定位 |
| `GET` | `/api/health` | 健康检查 |

例：

```bash
curl -s -X POST http://localhost:8000/api/typeset \
  -H 'Content-Type: application/json' \
  -d '{"text":"Hello 2026","width":16}'

curl -s -X POST http://localhost:8000/api/decode \
  -H 'Content-Type: application/json' \
  -d '{"text":"⠠⠓⠑⠇⠇⠕⠀⠼⠃⠚⠃⠋"}'

curl -s -X POST http://localhost:8000/api/avoid \
  -H 'Content-Type: application/json' \
  -d '{"front":"Hello Braille","back":"pack my box 2026","width":20,"min_distance":1.0}'

curl -s -X POST http://localhost:8000/api/inspect \
  -H 'Content-Type: application/json' \
  -d '{"text":"Hello 2026","width":16,"points":"0.1,0.2\n6.1,-0.1\n6.1,2.4"}'
```

## 离线说明

镜像基于 `python:3.11-slim`，仅在**构建镜像时**从 PyPI 拉取三个 Python 依赖；
运行后所有资源（HTML/CSS/JS、字体回退均使用系统字体）均由本服务自身提供，
不访问任何 CDN 或外部服务，可在断网环境中使用。

## 项目结构

```
.
├── app
│   ├── __init__.py

│   ├── avoid.py           # 双面点阵避让引擎（位移搜索与冲突枚举）

│       ├── style.css      # 样式（盲文格六点矩阵、点阵叠加图）
│       └── app.js         # 前端交互（原生 JS）
├── tests
│   ├── test_braille.py    # 排版引擎测试（含与独立 DP 的随机对照）
│   ├── test_reader.py     # 识读引擎测试（含排版→识读往返对照）
│   ├── test_avoid.py      # 避让引擎测试（含与朴素枚举的随机对照）
│   ├── test_inspect.py    # 复核引擎测试（含与朴素贪心枚举的随机对照）
│   └── test_api.py        # 接口层测试
├── Dockerfile
├── docker-compose.yml
├── requirements.txt
└── README.md
```

排版→识读往返一致性、双面避让的坐标映射/位移择优/冲突枚举与参数校验，
以及压印复核的坐标解析/错误定位/贪心配对/五级位移择优与缺失多余枚举，
